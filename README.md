# Эмулятор языка оболочки ОС

Учебный проект по дисциплине «Конфигурационное управление»
(ИКБО-41-25, Вариант №13). Практическая работа №1, Этап 2 (Конфигурация).

## 1. Общее описание

Приложение эмулирует работу в командной строке UNIX-подобной ОС.
Реализован графический интерфейс (GUI): пользователь вводит команды
в строку ввода, эмулятор разбирает их и выводит результат в область
вывода. Эмулятор настраивается параметрами командной строки и умеет
выполнять стартовый скрипт с командами.

Статус этапов:

- [x] Этап 1. REPL: заглушки ls, cd, команда exit.
- [x] Этап 2. Конфигурация: параметры командной строки, стартовый скрипт, conf-dump.
- [ ] Этап 3. Загрузка VFS из XML.
- [ ] Этап 4. Реальные команды ls, cd, а также uptime, tac.
- [ ] Этап 5. Команда touch.

## 2. Описание всех функций и настроек

Параметры командной строки:

- `--vfs-path ПУТЬ` — путь к физическому расположению VFS
  (на этапе 2 путь только запоминается и выводится, VFS ещё не читается);
- `--script ПУТЬ` — путь к стартовому скрипту с командами эмулятора.

Оба параметра необязательные.

При запуске в окно выводятся все заданные параметры (отладочный вывод).

Стартовый скрипт — текстовый файл, в каждой строке которого одна команда.
Скрипт выполняется построчно при запуске: в окне видно и ввод (строка
с приглашением `$`), и результат, как при ручном вводе. Пустые строки
пропускаются. Строки с ошибками пропускаются (выводится сообщение),
выполнение продолжается. Если файл скрипта прочитать нельзя, выводится
сообщение об ошибке.

Команды:

- `ls [аргументы]` — заглушка, выводит имя команды и аргументы;
- `cd [аргументы]` — заглушка, выводит имя команды и аргументы;
- `conf-dump` — выводит параметры эмулятора в формате `ключ=значение`;
- `exit` — завершает работу, не принимает аргументов.

Парсер поддерживает аргументы в кавычках: `cd "My Documents"` —
один аргумент. При неизвестной команде или неверных аргументах
выводится сообщение об ошибке, программа продолжает работу.

Заголовок окна содержит имя VFS: `MyVFS`.

## 3. Описание команд для сборки проекта и запуска тестов

Зависимости, кроме стандартной библиотеки Python (tkinter), не требуются.

Запуск приложения:

    run.bat
    run.bat --vfs-path vfs\my_vfs.xml --script startup_scripts\demo.txt

или

    python main.py --script startup_scripts\demo.txt

Скрипты для проверки параметров командной строки лежат в папке
`os_scripts` (test_no_args.bat, test_vfs_path.bat, test_script.bat,
test_both.bat, test_missing_script.bat).

Запуск тестов:

    python -m unittest discover -s tests -v

## 4. Примеры использования

Запуск со стартовым скриптом `startup_scripts\demo.txt`:

    run.bat --vfs-path vfs\my_vfs.xml --script startup_scripts\demo.txt

Результат в окне:

    --- параметры запуска ---
    vfs_path=vfs\my_vfs.xml
    script_path=startup_scripts\demo.txt
    -------------------------
    $ ls -la /tmp
    ls -la /tmp
    $ cd "My Documents"
    cd My Documents
    $ conf-dump
    vfs_path=vfs\my_vfs.xml
    script_path=startup_scripts\demo.txt
    $ qwerty
    ошибка: неизвестная команда: qwerty
    $ exit now
    ошибка: команда exit не принимает аргументов
    $ cd ..
    cd ..

Ручной ввод после выполнения скрипта:

    $ conf-dump
    vfs_path=vfs\my_vfs.xml
    script_path=startup_scripts\demo.txt
    $ exit

Если скрипт не найден:

    run.bat --script no_such_script.txt
    ошибка: не удалось прочитать скрипт no_such_script.txt: ...
